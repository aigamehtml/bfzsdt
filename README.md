# 定投导航仪（bfzsdt）

「百分之四定投法」基金定投辅助工具 —— Cloudflare Workers 一体化部署版。
按固定跌幅信号加仓、按回本信号止盈离场，把「跌 4% 买一笔」的纪律变成可执行的每日待办。

在线体验（数据为演示账号，请勿填入真实持仓）：<https://dingtou-worker.bfzs.workers.dev>

---

## 一、这是什么

「百分之四定投法」的核心规则：

1. **触发**：净值较上一笔成交价下跌 4%（即跌到上一笔的 96%）时，买入下一笔；
2. **加码**：每下一笔的买入金额是上一笔的 1.8 倍，共 10 笔一轮；
3. **止盈**：持仓整体反弹 5% 即回本，净值涨到「止盈目标净值」（默认 = 平均成本 ×1.2，即约 20%）时清仓离场，等待下一轮。止盈目标以**净值**设定，页面同时显示由成本换算的百分比。

本工具把上述规则落成三件事：

- **算清楚**：实时计算每只基金的理想阶梯表（触发价 / 买入金额 / 累计成本 / 剧本亏损锁线）；
- **提醒到**：净值刷新后自动判定六态信号（触发买入 / 可以离场 / 已投满……），列表置顶排序，可选邮件推送；
- **兜住底**：按真实持仓实算回本价，实际成交价偏离阶梯价时精算修正买入金额，避免「涨了 5% 却回不了本」。

> 本工具只做记录与计算，不代客理财、不提供投资建议。基金有风险，决策请独立作出。

## 二、功能特性

- **六态信号引擎**：未建仓 / 触发买入 / 本轮已止盈离场 / 建议止盈离场 / 10 笔已投满 / 净值异常，首页卡片按信号优先级排序
- **止盈目标净值化**：目标按净值设定（4 位小数），页面同时显示换算百分比（如「止盈 1.1000（+10.00%）」），净值到位即提醒；存量百分比数据自动兼容
- **理想阶梯表**：以首笔成交价为起点，推算 10 笔的触发价、金额、累计成本与「剧本亏损锁线」（最大浮亏上限）
- **双加仓模式**：
  - `ideal`（默认）：按理想阶梯表内金额买入，适合成交价接近阶梯价的场景；
  - `actual`：按「5% 回本」约束精算买入金额（成交价偏离越深，加码越多），偏离时自动覆盖表内金额
- **回本测算卡**：输入实际成交价，实时反推「从该价买入多少，才能涨 5% 回本」，支持偏离场景的金额决策
- **真实持仓口径**：回本价 = 总成本 ÷ 总份额（非经验法则的「最新价 × 1.05」），支持部分减仓后的剩余持仓
- **多账户隔离**：一个密码下可建多个账户（如「主力 / 实验」），数据互不可见
- **净值刷新**：对接东方财富公开接口，支持手动单只 / 全部刷新（定时任务已于 2026-11-25 停用）；净值日期按北京时间归属，并同步记录当日涨跌幅
- **数据自主**：JSON 导入 / 导出；设置页导出当前账户，`/api/data?scope=all` 可拿整库全量，数据永远属于你自己
- **信号邮件推送**：配置 Webhook 后，新加仓 / 止盈信号自动推送（异步、失败静默，不阻塞页面）
- **LLM 上下文导出**：`/api/llm-context` 一键导出当前持仓与信号的文本快照，方便让 AI 帮你解读；另有 `/api/data` 输出无提示词的纯数据备份（可选整库）；两者可配只读 API Key 供外部工具免登录抓取
- **首页日涨跌幅**：基金卡片现价旁显示净值日涨跌幅（涨红跌绿），净值日期是当天显示「今日」、否则「昨日」
- **精简运维页**：`/newdata` 只有「切换账户 + 更新数据」两件事，更新成功不弹窗、按钮文字变「已更新」
- **移动端适配**：单文件 SPA，375px 起可用，首页卡片、回本测算卡均为小屏优先布局

## 三、技术架构

一体化部署：**一个 Cloudflare Worker 同时承担 API 后端与前端静态资源托管**，同域同源，无需 CORS、无需独立服务器、无数据库运维。

```
浏览器（public/index.html，vanilla JS SPA）
   │  同域请求 /api/*
   ▼
Cloudflare Worker（worker.js）  ◄── 手动刷新（首页 / 详情页 / 精简页 /newdata）
   ├── 门禁：会话 Cookie（dt_session，7 天有效，SHA-256 令牌）
   │        例外：GET /api/llm-context · /api/data 可用 API Key 免登录（Secret LLM_CONTEXT_KEY，白名单只读）
   ├── API：/api/state · /api/funds · /api/records · /api/reductions · /api/settings …
   ├── 计算：信号引擎 / 阶梯表 / 回本精算（纯函数，与前端公式一致）
   ├── 外部依赖：东方财富净值接口 · 用户自配 Webhook（信号推送）
   └── 存储：KV namespace STORE
         ├── "store"    整份账户数据（accounts / fundsByAccount / currentAccount）
         ├── "settings" 加仓模式 + Webhook 地址
         └── "auth:*"   密码哈希 / 会话（KV 原生 TTL）
```

设计要点：

- **无框架依赖**：前端为单文件 vanilla JS，构建产物即源码，`wrangler deploy` 一把梭；
- **计算前后同源**：阶梯表、回本价、精算金额均在服务端计算后下发，前端展示与本地微调（回本测算卡）使用同一公式；
- **金额精度**：所有金额按「分」为最小单位运算，`Math.round(x * 100) / 100` 统一收口，不使用浮点累加；
- **时区**：Workers 运行时为 UTC，净值日期与记录日期一律按 `Asia/Shanghai` 归属，避免 0-8 点差一天。

## 五、快速开始

### 前置条件

- Node.js ≥ 18
- Cloudflare 账号（免费套餐即可，KV 有每日免费额度，个人使用绰绰有余）

### 部署（约 5 分钟）

```bash
# 1. 克隆仓库
git clone https://github.com/aigamehtml/bfzsdt.git
cd bfzsdt

# 2. 登录 Cloudflare（会打开浏览器授权）
npx wrangler login

# 3. 创建 KV namespace，并把返回的 id 填进 wrangler.toml
npx wrangler kv namespace create dingtou_store
# 输出形如：id = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
# → 编辑 wrangler.toml，替换 [[kv_namespaces]] 下的 id 值

# 4. 部署（自动上传 public/ 前端 + worker.js）
npx wrangler deploy

# 5.（可选）想让外部 AI / 脚本免登录抓取 /api/llm-context，再配置只读 API Key
openssl rand -hex 32                    # 生成密钥
npx wrangler secret put LLM_CONTEXT_KEY # 粘贴上一步输出
```

> 第 5 步可跳过：不配置时该接口仍只能由登录后的浏览器访问，其余功能不受影响。

部署完成后访问 `https://dingtou-worker.<你的子域>.workers.dev`，首次打开会要求**设置访问密码**（至少 6 位，哈希后存于 KV，不明文传输）。

> `wrangler.toml` 已关闭版本预览地址（`preview_urls = false`），对外只有 workers.dev 一个入口。

### 本地开发

```bash
npx wrangler dev          # 本地起服务（默认 http://localhost:8787）
```

本地产生的 `.wrangler/` 与 `data/` 已在 `.gitignore` 中，不会误提交。

## 六、使用说明

### 记一笔买入

1. 首页点「+ 添加基金」，输入基金代码（如 `018490`），自动拉取名称与净值；
2. 填首笔成交信息（成交价 / 份额 / 金额 / 日期），保存即建仓；
3. 之后每次触发信号，在基金详情页「记下一笔」录入实际成交信息。

### 六态信号

首页每张卡片带信号标签，列表按信号优先级排序：

| 信号 | 含义 | 操作建议 |
|------|------|----------|
| 触发买入 | 现价 ≤ 上一笔 × 0.96 | 按下一笔金额买入（详情页可见精算金额） |
| 建议止盈 | 现价 ≥ 止盈目标净值（默认成本 ×1.2，约 20%） | 记一笔卖出结算，本轮离场 |
| 本轮已止盈离场 | 已清仓，等待下一轮 | 清空买入记录后重新建仓 |
| 10 笔已投满 | 单轮 10 笔全部买入 | 持有等待止盈反弹 |
| 未建仓 | 尚无买入记录 | 录第一笔开始 |
| 净值异常 | 净值数据拉取失败 / 为 0 | 点「刷新数据」重试 |

### 止盈目标（净值口径）

止盈目标以**目标净值**设定（4 位小数），页面同时显示换算出的百分比——两者是同一条线的两种说法：

| 项 | 说明 |
|------|------|
| 存储字段 | `stopProfitNav`（目标净值，主口径）；`stopProfitTarget` 同步保留百分比，供导出备份 / 老版本读取 |
| 百分比换算 | `pct = (目标净值 ÷ 平均成本 − 1) × 100`，平均成本 = 累计成本 ÷ 持仓份额（已扣减仓） |
| 触发条件 | **现价 ≥ 目标净值**即判定「建议止盈」（与旧百分比口径等价，因为目标净值就是按成本换算来的） |
| 新建默认值 | 首笔成交价 × 1.2（即约 20%），可在弹窗里直接改 |
| 展示形式 | 详情页按钮 `止盈 1.1000（+10.00%）`；改止盈弹窗输入净值，下方实时显示 `≈ +15.00%（成本 1.0000）` |
| 无持仓时 | 份额为 0（如刚清仓）算不出平均成本 → 只显示目标净值，不显示百分比 |
| 存量数据 | 旧数据只有百分比（如 20%），读取时按当前平均成本自动反推目标净值，无需迁移 |
| 减仓后 | 平均成本变化 → 百分比随之重算，目标净值保持不变（净值是绝对值，不会因减仓漂移） |

> 举例：成本 1.0000，目标净值设 1.1000 → 详情页显示「止盈 1.1000（+10.00%）」，净值涨到 1.1000 即触发止盈提醒。

### 双加仓模式（设置页切换）

| 模式 | 金额口径 | 适用场景 |
|------|----------|----------|
| `ideal` 理想阶梯 | 表内序列金额（原始 10 档固定） | 成交价贴近阶梯价 |
| `actual` 实际回本 | 「5% 回本」精算金额，与表内金额取大 | 实付价偏离阶梯价（滑点 / 手动择时） |

> 两种模式下**触发价永远是理想阶梯价**（上一笔 × 0.96）——触发价只是「信号线」，实付价必然偏离；
> `actual` 模式修正的是**金额**，不是价格。

### 回本测算卡（基金详情页）

> 位置：详情页**最底部**（与「加仓计算表」一起排在最后）；详情页顶部信息卡下方有「📊 加仓计算表 / 🧮 5% 回本测算」两个横向按钮，点击可直接跳到对应卡片（跳转后目标卡会闪一下便于定位，滚动偏移已避开吸顶标题栏）。

输入你的**实际成交价**，实时计算：

- 以该价买入多少金额，才能做到「从该价涨 5% 恰好回本」；
- 若表内金额已足够，提示「表内金额已足够」；若不足，给出需加码的金额。

公式（服务端 `actualBuyAmount` 与前端同源）：

```
令 (cost + X) / (shares + X/P) = 1.05 × P
⟹ X = (cost − 1.05 × P × shares) / 0.05
```

其中 `cost` / `shares` 为当前真实持仓成本与份额，`P` 为输入的成交价。`X ≤ 0` 表示持仓已满足，无需加码。

### 多账户

设置页可新建 / 删除账户，首页顶部切换。账户间数据隔离，删除账户会同时删除其下基金数据（不可恢复，慎用）。

### 数据刷新与备份

- 「刷新数据」逐只更新净值；「全部刷新」一次更新当前账户全部基金；
- 设置页「导出数据」下载的是**当前账户**的 JSON（文件名含账户名）；「导入数据」支持单账户 / 全量两种格式；
- **整库备份**：设置页导出只覆盖当前账户。要一次拿全所有账户，用 `GET /api/data?scope=all`（见「纯数据快照」）；
- **建议定期导出备份**：KV 中的数据仅存于 Cloudflare，本地留一份最稳妥。

### 手动刷新净值（定时任务已停用）

**2026-11-25 起不再有每日自动刷新**：`worker.js` 已移除 `scheduled()`，`wrangler.toml` 的 `[triggers] crons` 已置空。净值更新改为手动触发：

- 看板首页「刷新数据」→ `POST /api/refresh-all`，刷新**当前账户**全部基金
- 详情页单只刷新 → `POST /api/refresh`
- 精简运维页 `/newdata` → 只做「切换账户 + 更新数据」两件事，适合手机上快速操作（见下节）

> 想恢复自动刷新：`wrangler.toml` 里把 `crons` 改回 `["5 16 * * *"]`（UTC 16:05 = 北京次日 00:05），并在 `worker.js` 里重新实现 `scheduled()`。注意只删代码不删配置**不会**停掉线上 cron——必须显式写 `crons = []` 才会清除。

刷新行为说明：
- 遍历当前账户全部基金，逐只隔离错误：单只失败只记入结果，不影响其他基金
- 抓取带 **8 秒超时**（东财接口偶发挂起，无超时会把整个请求拖到被终止）
- 净值曲线只解析**末尾 2000 字符**（`pingzhongdata` 有数千个点，全量正则很吃 CPU）
- 响应返回 `{ total, ok, fail, results: [{code, ok, dayChange?|message?}] }`，可直接看出哪只失败、原因是什么
- 每次刷新会把「净值日涨跌幅」一并写入，首页卡片直接展示

### 精简运维页 `/newdata`

访问 `https://<域名>/newdata`（需登录，与主站共用会话）只有一个极简页面：

| 功能 | 说明 |
|------|------|
| 切换账户 | 下拉选择，选中即生效，提示「已切换到「账户名」」 |
| 更新数据 | 刷新当前账户全部基金净值。**不弹提示框**，成功时按钮文字由「刷新数据」变为「已更新」，约 2.8 秒后自动复原 |

按钮文案随结果变化，避免手机上被弹窗打断：

| 结果 | 按钮文字 | 按钮下方说明 |
|------|----------|--------------|
| 进行中 | 更新中… | — |
| 全部成功 | 已更新 | `N 只基金已刷新 · 时:分` |
| 部分失败 | 部分失败 | `N 只已更新，M 只失败 · 时:分` |
| 全部失败 / 请求异常 | 更新失败 | 具体原因 |

> 页面本体是 `public/newdata.html`，由 Worker 在 `/newdata` 路由改写返回；未登录访问会落到登录页，不会暴露内容。

### 信号邮件推送

设置页填入 Webhook 地址（Zoho Mail webhook，`http(s)://` 开头），保存后可发一封测试邮件验证。配置后，每次打开首页检测到**新的**加仓 / 止盈信号即自动推送（异步执行、失败静默，不影响页面）；同一信号（按「信号类型 + 净值日期」去重）只推一次，不会反复轰炸。**定时任务已停用，推送只在打开看板时触发**。接口契约：POST JSON（`subject` / `content` / `summary` / `message`），成功判据为 HTTP 200 且响应体含 `"code":200`。

### 对外只读数据接口（LLM 上下文 / 纯数据快照）

两个接口共用同一把 API Key，都只放行 `GET`，都只读。区别只在**内容**：

| 接口 | 内容 | 范围 | 用途 |
|------|------|------|------|
| `/api/llm-context` | **加工后的分析快照**（层级 / 信号 / 精算金额 / 回本价）+ **内置提示词**；`?format=text` 输出「提示词 + 数据」纯文本，缺省 JSON | 当前账户 | 直接粘贴给 AI 做策略解读 |
| `/api/data` | **原始数据**，无提示词、无加工字段，格式与导入接口对齐，取 `data` 即可直接回灌 | **默认当前账户**；`?scope=all` 整库全部账户 | 自动备份、迁移、外部程序读原始数据 |

`GET /api/llm-context` 返回当前账户全部持仓、信号、精算金额与内置提示词的快照。两种访问方式：

| 方式 | 认证 | 适用场景 |
|------|------|----------|
| 浏览器登录后访问 / 设置页「复制提示词+数据」 | 会话 Cookie（`dt_session`） | 人工操作，前端自动带 Cookie |
| 外部程序直接抓 URL | **API Key**（`X-API-Key` 头或 `?key=` 参数） | 喂给 AI 工具、自动化脚本 |

**API Key 配置**（可选，不配置则接口维持「仅登录后 Cookie 可访问」）：

```bash
# 生成一个足够长的随机密钥（示例命令，输出仅你自己可见）
openssl rand -hex 32

# 注入为 Worker Secret（会提示粘贴，不写入任何文件、不进仓库）
npx wrangler secret put LLM_CONTEXT_KEY
# 本地开发另可放 .dev.vars：LLM_CONTEXT_KEY=xxxx（已加入 .gitignore）
```

调用示例（把 `<域名>`、`<密钥>` 换成自己的）：

```bash
# 推荐：密钥放请求头，不落在 URL / 浏览器历史 / 访问日志
curl -H 'X-API-Key: <密钥>' 'https://<域名>/api/llm-context?format=text'

# 图方便：密钥拼在 URL，方便直接把整条链接丢给只让填 URL 的 AI 工具
curl 'https://<域名>/api/llm-context?format=text&key=<密钥>'
```

**纯数据快照 `/api/data`**：

```bash
# 默认：仅当前账户，等价于设置页「导出数据」，可直接 POST 给 /api/import
curl -H 'X-API-Key: <密钥>' 'https://<域名>/api/data' | jq .data > backup-current.json

# 整库：全部账户 + 全部基金，可直接 POST 给 /api/import-all 恢复
curl -H 'X-API-Key: <密钥>' 'https://<域名>/api/data?scope=all' | jq .data > backup-all.json
```

返回结构（`scope=all` 时 `data` 为 `accounts` / `currentAccount` / `fundsByAccount`）：

```json
{ "success": true, "data": { "account": "主力", "funds": [ /* 原始 fund 对象 */ ], "exportedAt": "...", "scope": "current" } }
```

- **不含提示词 / 加工字段 / 设置项**：没有 `prompt`、`text`、`level`、`signal`、`breakevenPrice` 等，也不含 Webhook 地址与加仓模式；`funds` 是原始持仓对象（含 `records` / `reductions` / `stopProfitTarget`），与导入接口期望的格式一致。
- **范围默认最小**：不带 `scope` 只给当前账户，显式 `?scope=all` 才给整库；非法值返回 400，不静默回落（避免你以为备份了全库、实际只有单账户）。
- **可直接回灌**：`data` 部分 POST 给 `/api/import`（单账户）或 `/api/import-all`（整库）即可恢复，无需手工清洗字段；`scope` / `exportedAt` 是附加元信息，导入时会忽略。

注意事项（两个接口通用）：

- **白名单只读**：仅 `GET /api/llm-context` 与 `GET /api/data` 可用 API Key；`/api/state`、`/api/export`、`/api/settings` 等所有其他接口仍一律要求登录 Cookie，`POST` 到白名单路径同样被拦截。
- **未配置 Secret 时通道关闭**：请求回落统一门禁返回 401，不会因为没有配密钥就对外敞开。
- **密钥不落库**：Secret 由 Wrangler 注入运行时环境变量，不写入 `wrangler.toml`、KV、导出备份或前端页面；设置页不会显示它。轮换密钥重新执行 `wrangler secret put` 即可（无需改代码、无需重新部署）。
- **`?key=` 会留在 URL 里**：可能进入浏览器历史、代理/网关访问日志与 Referer。能控制请求头时优先用 `X-API-Key`；密钥泄露后应立即轮换。
- `?scope=all` 会一次性给出**所有账户**的完整持仓明细，暴露面比单账户大得多，密钥请按密码对待、勿公开分享。

## 七、API 一览

所有 `/api/*` 业务接口未登录均返回 401（OPTIONS 预检除外），**例外是白名单内两个只读 GET 接口**：`/api/llm-context` 与 `/api/data` 在配置了 Secret `LLM_CONTEXT_KEY` 时可用 `X-API-Key` 头或 `?key=` 免登录访问（详见「对外只读数据接口」）。业务接口统一返回 `{ success, ... }`。

## 八、策略参数

在 `worker.js` 顶部统一定义（与 PHP 原版口径一致）：

| 参数 | 值 | 含义 |
|------|-----|------|
| `LOSS_COEF` | 0.96 | 净值跌到上一笔的 96% 触发下一笔买入（跌 4%） |
| `ADD_MULT` | 1.8 | 理想剧本亏损锁线公式的分母参数 |
| `MAX_LEVEL` | 10 | 单轮层级上限（10 笔投满） |
| `BASE_SEQ` | 10, 10, 10, 20, 40, 72, 129, 233, 419, 755 | 基准加仓序列（原始 10 档固定，不随首投金额缩放） |
| `REBOUND_COEF` | 1.05 | 回本系数：下一笔买入后从买入价涨 5% 即回本 |
| `ADD_MODES` | ideal / actual | 加仓模式：理想阶梯 / 实际 5% 回本精算 |

理想剧本亏损锁线：`limit = (1 − LOSS_COEF) / (ADD_MULT − LOSS_COEF)` = 0.04 ÷ 0.84 ≈ **4.76%**
（含义：严格按阶梯表执行时，剧本内最大浮亏约为累计成本的 4.76%，这是纪律的代价上限。）

## 九、KV 数据结构

```
STORE（KV namespace）
├── store       # { accounts: [{name,color,createdAt}], currentAccount, fundsByAccount: {账户名: [fund] } }
│               # fund = { code, name, currentPrice, jzrq, records: [...], reductions: [...],
│               #          stopProfitTarget, remark }
├── settings    # { addMode: "ideal" | "actual", zohoWebhookUrl: string }
├── auth:pwd    # 密码哈希（SHA-256 直算，无盐；个人自用工具，勿存敏感密码）
├── auth:sess:*    # 会话令牌，TTL 7 天
└── cron:last  # 历史遗留键（定时任务已停用，仅旧数据残留，可忽略或删除）
```

## 十、安全说明

- 访问密码经哈希后存 KV，会话为 HttpOnly Cookie，7 天有效；
- 可选的只读 API Key 经 Wrangler Secret 注入（不入库），用常量时间比较校验，仅放行白名单内两个只读 GET（`/api/llm-context`、`/api/data`）；未配置即关闭，不会敞开数据；`/api/data` 默认只给当前账户，`?scope=all` 才给整库；
- 本地真实持仓数据（`data/`）与 `.dev.vars` 已在 `.gitignore` 中排除，仓库只含代码；
- 建议为 Cloudflare API Token 授予最小权限（Workers 编辑 + KV 编辑），并**在推送后及时吊销**；
- 本项目为个人自用工具，开源仅供学习交流，请勿直接部署为公开服务（无注册体系、无多人权限模型、无审计日志）。

## 十一、常见问题

**Q：首次打开是设置密码还是登录？**
A：KV 中无 `auth:pwd` 时显示设置密码页；已设置则显示登录页。

**Q：为什么触发价在 `ideal` / `actual` 下一样？**
A：触发价是信号线（上一笔 × 0.96），双模式一致；`actual` 只改买入金额。

**Q：修改密码后旧会话还有效吗？**
A：当前实现下，修改密码**不会**吊销已登录会话——旧 Cookie 仍有效直至 7 天自然过期。如需立即失效，请重新部署后清空 KV 中的 `auth:sess:*` 键。

**Q：把 `/api/llm-context?format=text` 发给外部 AI 工具，为什么返回 401？**
A：接口默认要求登录 Cookie，外部工具没有你的会话。在部署端执行 `npx wrangler secret put LLM_CONTEXT_KEY` 配置密钥后，用 `X-API-Key` 头或 `?key=` 携带即可免登录抓取；不配置则维持「仅登录后可用」。详见「对外只读数据接口」。

**Q：设置页导出的 JSON 是全部账户吗？**
A：不是，只含**当前账户**（文件名带账户名）。要一次拿全所有账户，用 `GET /api/data?scope=all`（需配 API Key），其 `data` 部分可直接 POST 给 `/api/import-all` 恢复。

**Q：数据会丢吗？**
A：数据存 Cloudflare KV，服务端多地冗余；但请自行定期「导出数据」留本地备份。
